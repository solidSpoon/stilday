# Stilday

主人的一天，写成 JSONL。

侧栏是「事件」+「采集器」+ 一份倒序的日历 + 设置：

- **事件**：汇总历史上所有事件，按天倒序；点一张卡片进入那一天。
- **采集器**：插件列表，每个插件有自己的启用开关、每日采集时间和插件
  设置（例如相册的同步范围）；顶部是系统每日分析时间，右侧只
  放分析任务；改动即时保存。
- **日历**：标题行只写列表顶部的年份，右边是「⌃ 今天 ⌄」；中间「今天」
  进入今天的界面，上下箭头按年跳。月份只写「10 月」，年份只出现在标题行
  和旧年份的分组里。侧栏默认宽档（380），右边缘点一下或拖一下切到窄档
  （320）。点日历上的任意日期，进入的是同一种界面。
- **某一天**：左边是资料，中间是事件，右边是对话。对话固定 370，可拖
  右侧分隔线在 240–480 之间调；资料和事件自由拖，素材 73 / 事件 27；拖
  资料/事件那条时对话宽度不变；日历侧栏默认宽档（380），右边缘点一下
  或拖一下切到窄档（320）；右上角「重置布局」回到 370 / 73 / 宽侧栏。
  - 资料：每张照片的大图缩略图；点大图打开 1600px JPEG 预览；当天合集
    现在显示在第一条分析用户消息里；最下面是 manifest.json
  - 事件：当天 AI 写出的事件时间流
- 日历从 **2020 年**到现在，本月在最上面；过去年份默认收起成一行年份，
  点一下展开，数据多的年份旁边有天数；当前月、滚动位置和选中日期所在年份
  会自动展开；整条列表是虚拟滚动的，82 个月也不会一次画完。

用 [MyGo](../mygo) 的原生 UI 写成：一个 Go 二进制，没有 webview，没有前端构建。

## 一天怎么工作

1. **设置里选存储目录**（只选一次）
   - 工作目录：每天的采集素材、合集、对话
   - 产物目录：每年一份 JSONL，一行一个事件
   - 照片不需要选目录：从 macOS 照片图库按拍摄时间自动取
2. **采集器：相册照片（全局）**
   - 采集器是插件：名字、描述、子文件夹、图标、执行函数，以及自己的 `View`
   - 全局配置在侧栏「采集器」页：相册同步最近 N 天、启用状态、采集时间、
     每日分析时间；每个插件都可以画自己的配置 UI
   - 配置写在存储根目录的 `collectors.json`，不是某一天
   - 每个采集器只写自己的子文件夹；执行前先清空它
- 系统统一给每个采集器、每一天算 **SHA256 指纹**：采集器文件夹的文件
  路径/大小/内容 + 影响采集结果的配置。状态这类生成物不进指纹
   - 目前只有「相册照片」一个，写 `previews/`、`thumbs/`、`sheets/` 和
     根目录的 `manifest.json`；不再保存原图副本
   - 「同步最近 N 天」逐天执行；当天的状态和手动执行都在采集器页
   - 每天 22:00 同步最近 N 天；第二天 10:00，在所有采集器都完成后，
     只把 **指纹和上次分析不一致** 的天放进 AI 队列；没变化的天不调用模型
   - 采集器页会显示「有变化 / 待分析」，并可以手动「分析 N 天」
3. **中间：对话**
   - 第一条用户消息不是技术指令，而是一句由临时 Pi 根据当天截图生成的、给朋友的开场白
   - 生成期间先在聊天里显示截图和三个点的输入动效，拿到后直接发送
   - 当天全部合集作为图片附件随这条消息发给模型，聊天里也全部显示
   - 每张照片的 manifest 还带相册、收藏、地点、相机/镜头/ISO/光圈/快门/焦距、Live Photo/截图/全景/HDR/景深、编辑/连拍等元数据
   - 模型可以调用：
     - `day_overview`：再看一遍合集
     - `read`：直接读 `previews/012.jpg` 看某一张的细节
     - `stilday_emit({entries})`：把事件写成 JSONL
   - 每次分析都清空旧对话和旧事件，新开一个 Pi 会话
4. **日期页：资料 / 事件 / 对话**
   - 资料（第一列，比事件宽）：照片的大图缩略图；点大图打开 `previews/`
     里的 1600px JPEG。当天合集在第一条分析用户消息里，不再占用资料栏。
     照片的收集和整理在「采集器」页。
   - 事件（第二列）：当天的事件卡片流，按时间正序
   - 对话（第三列，固定 370）：顶部是带外框的头像 + 玻璃胶囊（Stilday ›），
     整块不可见区域都可点，弹出中间的 system prompt 弹窗；下面是消息列表和
     输入框；分析/重新分析也从这里的输入条发起
   - 两条分隔线：左边那条自由调资料/事件（默认 73 / 27），拖它时对话
     宽度不变；右边那条调对话宽度（240–480），资料/事件按比例分剩下的；
     日历侧栏右边缘切换窄/宽两档；右上角的「重置布局」回到 370 / 73 /
     宽侧栏
5. **对话输入**
   - 输入框默认一行，随文字长到五行；Enter 发送，Shift+Enter 换行
   - 左边圆按钮是「分析这一天 / 重新分析这一天」：空白的一天直接开始；
     已有事件或对话时会先确认，删掉当天的事件和对话，重新整理照片并重新
     生成；右边圆按钮是发送
   - 空对话就是空白的（像短信），不放开始按钮；资料/事件列为空时显示居中
     的图标、标题和说明，分析只从输入条发起
   - 自己说的话是蓝色气泡靠右，AI 的 Markdown 平铺在左侧；工具调用是灰色小条
6. **采集器状态**
   - 侧栏「采集器」是全局页面：中间是插件设置，每个插件有自己的自定义 UI
     和「同步最近 N 天」/「运行今天」；右侧是「采集计划」和「分析任务」
   - 插件列表里的每一行都是一个插件：启用/禁用开关、每天几点自动执行、
     「立即执行」，然后才是这个插件自己的设置；相册的同步范围、启用状态和
     采集时间写进 collectors.json，每日分析时间写进 config.json，没有保存按钮
   - 列表顶部是「每日分析」：所有启用的插件完成后，到这个时间才分析右侧
     待分析的天（默认 10:00）
   - 右侧「分析任务」：分析中、排队中、待分析、已取消、最近完成；每天一行，
     可以「取消」待分析/排队的任务，取消后可以「恢复」
   - 任务栏顶部是一键控制：暂停/继续、重启、取消全部、清除已完成；暂停只停
     队列，当前这天会跑完；重启会清掉取消状态重新排队；取消全部会停掉当前
     并取消队列
   - 分析运行中，侧栏底部会出现「分析中 · 队列 N」，点它回到任务列表
   - 每行只显示图标、名字、描述和上次状态；图库路径、子目录这些内部细节不露出来
   - 「立即执行」会先清空该采集器的子文件夹，再重新收集
   - 每个启用的插件按自己的每日时间执行（相册默认 22:00）；所有启用的插件
     完成后，待分析的天出现在右侧，到「每日分析」的时间自动开始
   - 设置页只留存储、模型、Pi 和 AI 入口；没有常驻的「取消 / 保存」，改动后
     右上角才出现一个玻璃勾
   - 全局配置在 `<存储根>/collectors.json`；每个采集器每天的运行状态写在
     当天的 `collectors.json`，同时汇总进 `manifest.json`
7. **事件**
   - 所有历史事件，按处理日倒序，每天一个分组标题
   - 点卡片进入那一天，并在「事件」里定位到它
   - 可以搜索所有事件

## 存储布局

设置里只选一个根目录，Stilday 在里面分两棵树：

```
<存储目录>/
  collectors.json            全局采集器配置（最近 N 天、照片时间来源）
  work/
    2026/10/23/                每天的工作目录
      manifest.json            当天采集器、照片、文件的总清单
      collectors.json          每个采集器当天的状态、指纹、是否变化、已分析指纹
      previews/                1600px JPEG 预览（模型读取用）
      thumbs/                  360px 界面缩略图
      sheets/01.jpg            编号合集
      chat.jsonl               对话记录
      system.md                当天给模型的系统提示
      .pi/                     Pi 会话
  artifacts/
    2026.jsonl                 当年的产物：一行一个事件
```

工作目录按年/月分组；产物每年一个文件；换存储目录不会搬走旧文件。

事件格式：

```json
{"occurred_at":"2026-10-23T14:05:00+08:00","updated_at":"2026-10-24T09:12:00+08:00","day":"2026-10-23","kind":"place","summary":"在 Blue Bottle 写了两个小时代码"}
```

| 字段 | 含义 |
| --- | --- |
| `occurred_at` | 事件发生时间，RFC 3339，带本地时区 |
| `updated_at` | 这条记录最后一次写入/更新时间 |
| `day` | 这一行被处理/归入的日期；重新分析时按它整体替换 |
| `kind` | 事件类型，例如 `place`、`task`、`person` |
| `summary` | 一句描述 |

AI 入口就在设置页：年度产物文件的路径，可一键复制。任何能读文件的助手
都能从这里获得这一年的上下文。

## 需要 Pi

对话由 Pi 驱动（RPC 模式），照片整理不需要 Pi。

**第一次使用**：

1. 在设置页的 Pi 卡片点「下载 Pi v1.4.0」。Stilday 会从 Pi 的 GitHub
   release 下载当前平台的 standalone binary（约 30–45 MB），校验 SHA256，
   解压到应用私有目录：
   ```
   ~/Library/Application Support/stilday/pi/1.4.0/
   ```
   不需要 Node，也不需要系统里预装 `pi`。
2. 在设置页的模型卡片选 **OpenCode Go** 的模型，并填 API key（在
   [opencode.ai](https://opencode.ai) 获取）：
   - Provider：`opencode-go`
   - Model：在「模型」弹窗里搜索选择，例如 `deepseek-v4.1-flash`
   - 环境变量：`OPENCODE_API_KEY`
   key 存在 macOS Keychain，不写进配置文件。保存后直接对话即可，不需要
   终端登录。
3. 也可以选择「在终端登录」：打开下载好的 Pi，输入 `/login`，登录信息在
   `~/.pi/agent`，Stilday 共用。

- `STILDAY_PI` 可以指定另一个 `pi`，优先于下载的版本
- 模型列表从 OpenCode Go 的 `/inference/go/v1/models` 拉取（`x-api-key`），
  Pi 的本地 catalog 只补显示名；`provider.go` 里加一项就能接其他 provider
- Pi 的版本固定在 `piVersion`（`piinstall.go`），应用升级时一起更新

Stilday 启动 Pi 时只加载自己的扩展（`pi/stilday.ts`，运行时写到
`~/.stilday/pi/`），只开放三个照片/输出工具，并关掉其他扩展、技能、MCP 和项目
上下文文件。

## 照片

- 默认用 **官方 PhotoKit**：首次同步时编译一个很小的 Swift 助手
  （`Stilday Photos.app`），用 `PHAsset.creationDate` 和 `PHImageManager`
  导出原图数据来生成预览；macOS 会弹一次照片图库权限
- 需要 Xcode Command Line Tools 的 `swiftc`；助手只编译一次，之后复用
- 如果 PhotoKit 不可用或被拒绝，退回读取 `~/Pictures/Photos Library.photoslibrary`
  的 `originals`
- `STILDAY_PHOTOS_LIBRARY` 可以指向另一个照片图库
- 照片库里的文件，Spotlight 的 `kMDItemContentCreationDate` 常常是导入/整理
  日期，不是拍摄日期（会把 2016 年的照片放进 2026 年）
- 照片按拍摄时间归日，导入时间只作兜底：
  - 拍摄时间：PhotoKit 的 `PHAsset.creationDate`（官方拍摄日期）；助手不可用时
    用 `sips` 的 EXIF/creation，仍拿不到再退回导入时间
  - 照片按拍摄时间归到某一天；没有 EXIF 时依次退回 Spotlight 内容日期和文件日期
  - 云相册拿不到拍摄日期时，导入日期是合理的兜底
- `sips` 读 HEIC 和照片库元数据，也生成预览
- 其他平台只保证 JPEG / PNG
- 一天最多均匀采样 120 张，避免几千张照片撑爆上下文
- 合集是给模型的**总览**：6×5 格、每格 300×225；放不下才生成多张
- 不保存原图副本。`previews/` 是 1600px 的 JPEG，`thumbs/` 是 360px 的
  界面缩略图；HEIC 也在生成预览时转成 JPEG
- 细节不另做工具：模型用 `read` 打开每张照片的 `read` 路径，也就是
  `previews/` 里的 1600px JPEG
- `manifest.json` 是当天资料的完整索引：每张照片的拍摄时间、原图尺寸、
  预览字节数、格式、所在合集和格子；它把合集格子和照片双向映射起来，还
  列出所有预览/缩略图/合集文件（`files`）

一个照片条目大致是：

```json
{
  "index": 1,
  "preview": "previews/001.jpg",
  "thumb": "thumbs/001.jpg",
  "read": "previews/001.jpg",
  "captured_at": "2026-10-23T08:41:41+08:00",
  "sheet": 1,
  "sheet_file": "sheets/01.jpg",
  "cell": 1,
  "cell_row": 1,
  "cell_col": 1,
  "width": 1179,
  "height": 2556,
  "bytes": 977643,
  "format": "png"
}
```

合集里还有 `cells: [{photo, row, col}]`，和照片的 `sheet`/`cell` 对应；
`files` 把当天所有资料文件摊平，方便人和脚本直接扫。

## 隐私

照片只从照片图库读取，工作目录里只保留 1600px JPEG 预览和 360px 缩略图；
**合集和模型用 `read` 打开的预览会通过 Pi 发给模型提供商**。
不要把照片图库指向你不想上传的内容。

Pi 以你的用户身份运行。Stilday 只开放 `day_overview`、`read`、`stilday_emit`
三个工具。

## 运行

```sh
go tool mygo dev      # 开发，热重载
go tool mygo build    # 打包成 .app / .dmg
go test               # 不打开窗口，直接测试视图和协议
```

要求 Go 1.27+。`go.mod` 通过 `replace` 指向同级的 `../mygo` 检出。

## 配置

应用设置写在 `~/.stilday/config.json`（`STILDAY_HOME` 可改），由设置页维护。
API key 不在这里，存在 macOS Keychain：

```json
{
  "storage_dir": "~/Stilday",
  "photo_start": "09:00",
  "photo_end": "22:00",
  "max_photos": 120,
  "provider": "opencode-go",
  "model": "deepseek-v4.1-flash",
  "collect_time": "22:00",
  "auto_time": "10:00"
}
```

## 代码

按职责分层：根目录是 `package main`（窗口和所有页面），没有 UI 依赖的领域
放在 `internal/`，Pi 协议在 `agent/`。边界和「改代码前要守住的规则」见
[docs/architecture.md](docs/architecture.md)。

| 文件 / 包 | 内容 |
| --- | --- |
| `main.go` | 窗口 |
| `app.go` | 应用状态、窗口壳、换天、产物载入 |
| `sidebar.go` / `calendar.go` | 侧栏导航、年份步进、日历行与采集标记 |
| `day.go` / `panels.go` | 一天的头部与三栏；资料、事件、分析动作 |
| `board.go` | 全局事件：所有事件、倒序、按天分组、搜索 |
| `chat.go` / `chat_store.go` | 一天的会话状态、transcript 读写 |
| `chat_agent.go` / `chat_prompt.go` | Pi 进程生命周期、事件流；系统提示与 `stilday_emit` |
| `chat_message.go` / `chat_composer.go` | 消息与工具行、输入条与发送 |
| `greeting.go` | 开场白的一次性 Pi 会话 |
| `internal/artifact` | 事件行格式、年度 JSONL 读写与旧格式迁移 |
